## 这玩意儿是干嘛的？

用大白话说：**DiagMaster 就是个服务器"体检仪"**。

你只需要在终端里敲一行命令，然后像看电视遥控器一样按数字键，它就能帮你：

| 功能 | 通俗解释 |
|------|----------|
| 🖥️ **性能监控** | 看看 CPU 累不累、内存够不够、磁盘满没满 |
| 🔍 **日志审计** | 检查有没有人偷偷暴力破解你的服务器密码 |
| 🧹 **磁盘清理** | 一键清空系统垃圾文件，释放空间 |
| 🚨 **自动巡逻** | 定时全身体检，有毛病立刻告诉你 |
| 📋 **节点管理** | 管理多台服务器，像电话簿一样记下它们的地址 |

**不需要你会 Linux 命令**，全程菜单操作，输入数字就行。

## 怎么安装？

### 你需要什么前提条件？

- ✅ 一台装了 Ubuntu 的电脑 / 服务器 / WSL（Windows 自带的 Linux 子系统）

这个项目**不需要安装任何额外的东西**，所有工具都是 Linux 自带的。

### 安装步骤（3 步）


**完成了！** 然后运行 `bash diagmaster.sh` 即可。

## 主菜单都干什么？

下面逐一说明每个功能怎么用。

---

### 1. 服务器节点资产管理

> 通俗理解：**像一个电话簿，记下你管理的所有服务器地址**

进入后子菜单：

```
 1) 查看当前受控节点列表    ← 看看记了哪些服务器
 2) 新增受控服务器节点       ← 添加一台新服务器
 3) 删除失效服务器节点       ← 删掉不用的
 4) 返回主菜单
```

#### 示例：添加一台服务器

```
请输入子菜单指令 (1-4): 2
请输入要添加的服务器IP/名称: 192.168.1.100
✓ 节点添加成功。
```

就这样，192.168.1.100 被记录下来了。数据保存在 `data/nodes.txt` 文件里。

---

### 2. 性能指标并行监控

> 通俗理解：**同时量三个指标，看看服务器"累不累"**

选择后会同时检测：

- **CPU 使用率** — CPU 有多忙，太高说明服务器在"拼命干活"
- **内存使用率** — 内存用了多少，太高说明内存快不够用了
- **磁盘使用率** — 硬盘满了多少，太高说明该清理了

输出示例：

```
 CPU: 15.2%  | 内存: 42.3%  | 磁盘: 55%
```

| 指标 | 绿色安全 | 黄色警告（默认） | 红色危险 |
|------|-----------|-----------------|----------|
| CPU | < 80% | 80%-95% | > 95% |
| 内存 | < 85% | 85%-95% | > 95% |
| 磁盘 | < 90% | 90%-95% | > 95% |

> 阈值可以在 `config/diag.conf` 里改，参考[配置章节](#怎么修改配置)

---

### 3. 内核日志清洗与安全审计

> 通俗理解：**像保安查监控，看看有没有坏人试图破解你的服务器**

自动检查两件事：

1. **OOM 事件** — 系统内存不够导致"杀进程"，就像房间太小要把东西扔出去
2. **SSH 爆破** — 有没有人反复尝试猜你的密码

输出示例：

```
 OOM 事件: 0 次  | SSH 爆破尝试: 3 次
✓ 报告已输出至: ./reports/diag_report_20260606_181237.md
```

SSH 爆破为 0 就是安全，如果数字很大（比如几百上千次），说明有人在暴力破解你的服务器，需要立刻处理。

检测完成后会自动生成一份 Markdown 报告，在 `reports/` 文件夹里可以查看。

---

### 4. 智能化磁盘清理

> 通俗理解：**一键倒垃圾，清理系统临时文件**

```
--- [模块 4] 磁盘临时文件清理 ---
确认清理 /tmp 下临时文件? (y/n):
```

- 输入 `y` + 回车 → 清理（清空 `/tmp` 下的临时文件）
- 输入 `n` + 回车 → 取消

> ⚠️ 只会清理 `/tmp` 下的临时文件，不会动你的重要数据。但如果你不确定 `/tmp` 里有没有重要东西，建议先选 n。

---

### 5. 自动巡逻巡检

> 通俗理解：**医生查房，一次性检查 6 个项目，全部正常才放心**

这是最核心的功能，一键检查：

| 序号 | 检查项 | 检查什么 |
|------|--------|----------|
| 1 | CPU 使用率 | 是否超过阈值（默认 80%） |
| 2 | 内存使用率 | 是否超过阈值（默认 85%） |
| 3 | 磁盘使用率 | 是否超过阈值（默认 90%） |
| 4 | 关键服务 | sshd、cron 是否在正常运行 |
| 5 | 关键进程 | 重要进程是否存在 |
| 6 | 日志异常 | 是否有 OOM / SSH 爆破 |

检查完会输出结论：

- ✅ `巡逻完成：系统状态正常。` — 一切安好
- ⚠️ `巡逻完成：发现异常项，请查看报告。` — 有毛病，去 reports 文件夹看报告

同时会在 `reports/` 目录生成详细的巡逻报告（Markdown 格式），可以打开看每个指标的详细状态。

## 怎么修改配置？

配置文件在这里：**`config/diag.conf`**

用任意文本编辑器打开（比如 vscode、nano、vim），你会看到：

```bash
# 性能阈值（改这 3 个数字就行）
CPU_WARN_THRESHOLD=80      # CPU 超过 80% 就报警
MEM_WARN_THRESHOLD=85      # 内存超过 85% 就报警
DISK_WARN_THRESHOLD=90     # 磁盘超过 90% 就报警

# 登录账号密码（强烈建议改成你自己的）
ADMIN_USER="admin"          # 把 admin 换成你的用户名
ADMIN_PASS="12345"          # 把 12345 换成你的密码

# 巡逻要检查的服务和进程（空格分隔）
SERVICES_TO_CHECK="sshd cron"      # 检查哪些服务
PROCESSES_TO_CHECK="sshd"          # 检查哪些进程

# 邮件告警开关
ENABLE_ALERT=false                 # true=开启邮件告警，false=关闭
ALERT_EMAIL="admin@example.com"    # 告警发送到哪个邮箱
```

### 修改示例

**想改成自己的密码？**

```bash
# 用 nano 打开配置文件
nano config/diag.conf

# 找到这一行
ADMIN_PASS="12345"

# 改成
ADMIN_PASS="MySecureP@ss2024"

# Ctrl+O 保存，Ctrl+X 退出
```

**想增加巡逻检查的服务？**

```bash
# 原来的：
SERVICES_TO_CHECK="sshd cron"
# 改成（比如还想检查 nginx）：
SERVICES_TO_CHECK="sshd cron nginx"
```

**改完配置后不需要重启任何东西**，下次运行自动生效。

```markdown
- 生成时间: Sat Jun  6 19:37:49 CST 2026
- 主机名: my-server
- 系统负载: 0.01, 0.02, 0.00

## 检查结果汇总
**整体状态: 正常 ✅**

| 检查项 | 状态 | 详情 |
|--------|------|------|
| CPU使用率 | 正常 | 阈值:80% |
| 内存使用率 | 正常 | 阈值:85% |
| 磁盘使用率 | 正常 | 阈值:90% |
```

## 常见问题（QA）

### Q: 运行时报错 "Permission denied" 怎么办？

```bash
# 加运行权限
chmod +x diagmaster.sh
chmod +x modules/*.sh
chmod +x lib/*.sh
```

### Q: 忘记密码了怎么办？

打开 `config/diag.conf`，找到 `ADMIN_PASS` 那行，改掉。或者直接删除这一行，默认密码会变成 `12345`。

### Q: 巡逻报告说"无法获取磁盘使用率"？

可能是 `df` 命令不可用，或者权限不够。试试：

```bash
df -h /
```

如果能正常输出，那说明脚本没问题；如果不能，你可能需要安装 `coreutils`。

### Q: 我想检查更多服务怎么办？

修改 `config/diag.conf` 里的 `SERVICES_TO_CHECK` 变量。

比如想增加 nginx 和 mysql：
```bash
SERVICES_TO_CHECK="sshd cron nginx mysql"
```

### Q: 邮件告警怎么开启？

1. 先确保服务器装了 `mail` 命令：`sudo apt install mailutils`
2. 修改 `config/diag.conf`：
   ```bash
   ENABLE_ALERT=true
   ALERT_EMAIL="你的真实邮箱@example.com"
   ```
3. 这样巡逻发现异常时，会自动发邮件给你。

### Q: 能在别的 Linux 系统上用吗？

理论上只要是 Linux 就行（CentOS、Debian、Arch 等），但部分功能依赖：
- `systemctl`（服务检查，没有会自动降级用 `pgrep`）
- `/var/log/auth.log`（SSH 审计日志，不同的发行版可能路径不同）

Ubuntu/Debian 环境体验最佳。

### Q: 运行会不会搞坏我的服务器？

**不会**。这个脚本只做**读取和报告**，唯一的"写入"操作是：
- 清理 `/tmp`（需要你手动确认 y/n）
- 生成报告文件
- 写运行日志

绝对不会删除你的重要文件或修改系统配置。

### Q: 怎么让巡逻定时自动运行？

使用 Linux 自带的 cron：

```bash
# 编辑定时任务
crontab -e

# 添加一行（每天早上 8 点自动巡逻）：
0 8 * * * cd ~/diagmaster/diagmaster && bash modules/patrol.sh >> logs/cron_patrol.log 2>&1
```

## 安全提示

| 事项 | 说明 |
|------|------|
| 🔐 **改密码** | 默认密码 `12345` 仅用于演示，请立即修改 |
