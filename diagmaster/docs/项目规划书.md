## 二、需求分析

### 2.1 谁在使用系统？

- **小型网站维护人员**（如个人博客站长、小型企业IT兼职人员）：日常需要检查服务器是否正常运行，但缺乏专业的运维工具（如 Prometheus、Zabbix）的配置能力。
- **树莓派/云服务器初学者**：希望用最简单的交互了解自己服务器的健康状况。
- **课程学习者**：通过本项目的代码和文档学习 Linux Shell 脚本的工程化实践。

### 2.2 实际问题是什么？

1. **服务器健康状态不可见**：小型服务器经常因日志累积、CPU飙高、磁盘满等问题导致服务不可用，但维护者往往在问题发生后才感知。
2. **SSH安全风险被忽视**：暴露在公网的服务器每天遭受大量暴力破解尝试，但维护者缺乏简易手段快速检查安全风险。
3. **多台服务器管理繁琐**：手工逐台登录检查效率低，缺少统一的节点资产管理方式。

> 这些问题都是**可观察、可验证**的——磁盘是否满可以用 `df` 查验，SSH 爆破可以用 `grep "Failed password" /var/log/auth.log` 计数，CPU 使用率可以用 `top` 查看。

### 2.3 现有方法为什么不好用？

| 现有方法 | 缺陷 |
|----------|------|
| 手工执行 `top`、`df`、`free` 等命令 | 需要记住命令、逐台逐指标查看，不直观、无自动巡检能力 |
| 安装 Prometheus + Grafana | 配置复杂、资源消耗大，对小服务器"杀鸡用牛刀" |
| 云厂商自带监控 | 需额外付费、仅限特定平台、无法自定义巡检项 |
| 人工定期巡检 | 低效、容易遗漏、缺乏持久化报告记录 |

### 2.4 项目具体解决什么问题？

- **一键自动巡检**：输入一个数字即可自动完成6项健康检查（CPU/内存/磁盘/服务/进程/日志安全），并生成 Markdown 格式报告。
- **多源日志安全审计**：自动扫描 dmesg、auth.log、syslog 等日志，检测 OOM、SSH 暴力破解、sudo 异常等风险。
- **配置化阈值告警**：用户可自定义 CPU/内存/磁盘告警阈值，无需修改代码。
- **自动化测试保障**：14个单元/集成测试覆盖正常、异常、边界场景，确保模块可靠。

### 2.5 最核心的 1~2 个功能

1. **自动巡逻巡检**：一键式6项检查（CPU/内存/磁盘/服务/进程/日志）+ 报告生成，这是系统最核心的价值——从"手工检查"变为"一键体检"。
2. **日志清洗与安全审计**：多源日志聚合分析（dmesg + auth.log + syslog + kern.log），检测 OOM、SSH 爆破、内核错误、sudo 异常，生成结构化报告并给出修复建议。

## 三、技术方案

### 3.1 技术选型

| 技术 | 用途 |
|------|------|
| **Bash 脚本** | 主程序与所有模块的开发语言，零依赖 |
| **grep / sed / awk** | 文本处理、日志过滤、数据提取 |
| **管道与重定向** | 进程间数据传递、错误输出控制 |
| **并发进程**（& + wait） | 性能指标并行采集，缩短巡检时间 |
| **模块化设计**（source） | 代码解耦：配置/库/模块/测试分离 |
| **systemctl / pgrep** | 服务与进程状态检测 |
| **dmesg / /var/log** | 内核与系统日志分析 |
| **crontab** | 定时自动巡检 |
| **Git** | 版本控制，完整 commit 历史 |
| **Mock 测试框架** | 自动化测试，模拟正常/异常/边界场景 |

### 3.2 系统架构

```
┌───────────────────────────────────────────────┐
│                   diagmaster.sh               │
│               (主入口，菜单路由)                │
└──────┬────────┬────────┬────────┬─────────────┘
       │        │        │        │
       ▼        ▼        ▼        ▼
┌─────────┐ ┌──────┐ ┌──────┐ ┌──────────┐
│collector│ │log   │ │patrol│ │ 磁盘清理  │
│ .sh     │ │analy-│ │.sh   │ │ (内联)    │
│(性能)   │ │zer.sh│ │(巡检)│ │           │
└────┬────┘ └──┬───┘ └──┬───┘ └──────────┘
     │         │        │
     └────┬────┴────┬───┘
          ▼         ▼
     ┌────────┐ ┌──────┐
     │lib/     │ │config│
     │utils.sh │ │diag. │
     │assert.sh│ │conf  │
     └────────┘ └──────┘
```

### 3.3 模块划分

| 模块 | 文件 | 职责 |
|------|------|------|
| 主程序 | `diagmaster.sh` | 安全认证、菜单路由、模块调用 |
| 性能采集 | `modules/collector.sh` | CPU/内存/磁盘并行采集、阈值告警、历史对比 |
| 日志审计 | `modules/log_analyzer.sh` | dmesg/auth.log/syslog 多源分析、报告生成 |
| 巡逻巡检 | `modules/patrol.sh` | 6项系统健康检查、Markdown 报告、邮件告警 |
| 公共库 | `lib/utils.sh` | 日志函数、数值比较、命令存在检查 |
| 断言库 | `lib/assert.sh` | 测试断言（equal/contains）、结果汇总 |
| 配置 | `config/diag.conf` | 阈值、认证、服务/进程列表 |
| 测试 | `tests/test_patrol.sh` | 14个 Mock 测试用例 |
