## 第1页：项目简介

**标题**：DiagMaster — 服务器一键多维智能诊断工具箱

**内容**：
- **项目名称**：DiagMaster v3.0
- **团队**：翟浩雯（组长）、李薇（组员）
- **服务对象**：小型网站自运维管理员、轻量云服务器用户、WSL 独立开发者
- **解决痛点**：服务器健康状态不透明、多维指标数据断层、安全隐患信息盲区、缺少零依赖的一键巡检工具
- **定位口号**：像量体温一样简单，输入数字即可完成服务器体检

## 第2页：需求与目标

**现有方法缺陷**：
- 手动执行 `top`、`df`、`free`、`dmesg` 等十多个离散命令 — 操作繁琐、无法横向关联分析（耗时 5~15 分钟）
- 搭建 Prometheus + Grafana 等监控体系 — Agent 部署复杂、服务端依赖重、额外占用大量系统资源，单机无法落地
- 人工巡检 — 低效且容易遗漏，深夜安全事件完全处于信息盲区

**核心目标（具体可验证）**：
- 一键自动巡检 6 项健康指标（CPU / 内存 / 磁盘 / 关键服务 / 关键进程 / 日志安全）
- 8 阶段深度安全审计：多源日志清洗、SSH 爆破检测、攻击模式识别（端口扫描 / 用户枚举 / 权限提升 / 恶意软件）、加权风险评分
- 支持后台守护进程模式（nohup + PID 管理），实现无人值守定时巡逻
- 输出 Markdown + JSON 双格式结构化报告，兼容 crontab 定时任务
- 阈值配置化（`config/diag.conf`），用户无需修改代码即可自定义报警线
- 75 个自动化测试用例全覆盖，Mock 机制 + 真实环境双层验证

| 技术项 | 实际应用 |
|--------|---------|
| Bash 脚本编程 | 全部功能开发与主控逻辑（~3400行），`set -uo pipefail` 严格错误处理 |
| `grep` | 日志关键词过滤（OOM/BUG/panic）、SSH 爆破 IP 提取、sudo 白名单过滤 |

| `sed` | 文本清洗、ANSI 颜色码过滤、特殊符号去除 |
| 管道 / 重定向 | 多命令组合、静默权限错误（`2>/dev/null`）、日志输出重定向至 `stderr` |
| 并发进程 (`&` + `wait`) | 并行采集 CPU/内存/磁盘三项指标，10 秒超时强制 `kill -9` 防死锁 |
| `systemctl` / `pgrep` | 服务状态检测（`systemctl is-active`）与自动降级处理（`pgrep -x`） |
| `dmesg` / `/proc` 文件系统 | 内核日志分析（OOM/Kernel Panic）、`/proc/loadavg` 负载采集、`/proc/meminfo` 内存精确计算 |
| `crontab` / `systemd` | 定时任务调度 + systemd 服务模板（`diagmaster-patrol.service`） |
| SSH 分布式通信 | `test_ssh_connection` / `test_ssh_key_auth` / `collect_remote` 远程采集 |
| Git 版本控制 | 全程版本控制，Conventional Commits 规范 |
| Mock 测试 | 离线模拟 `top`/`free`/`df`/`systemctl` 等命令输出，覆盖功能/边界/异常/自动化四类场景 |

## 第5页：核心功能展示

**功能1：交互式一键诊断（6 大模块，7 个菜单）**

```
  🚀 快速操作入口
  1) 节点资产    2) 性能监控    3) 安全审计    4) 磁盘清理
  5) 自动巡检    6) 后台守护    7) 关于项目    0) 安全退出
```

- **节点资产**：分布式服务器管理，三重 SSH 验证，批量远程诊断
- **性能监控**：多进程并行采集（CPU/内存/磁盘/负载/进程数），颜色阈值告警（绿/黄/红）
- **安全审计**：8 阶段深度分析，攻击模式识别，加权风险评分（0-100）
- **磁盘清理**：7 源智能扫描（/tmp/cache/Trash/apt/journal/旧内核/Docker），风险分级 + 自愈
- **自动巡检**：6 项健康指标一键检查，异常即告警
- **后台守护**：nohup 守护进程 + PID 管理，定时巡逻，自愈修复

**功能2：安全审计 — 8 阶段深度分析**

```
[1/8] 检测可用日志源 → [2/8] 分析内核日志 → [3/8] 审计SSH安全
→ [4/8] 检测攻击模式 → [5/8] 清洗系统日志 → [6/8] 关联事件分析
→ [7/8] 计算风险评分 → [8/8] 检测历史异常
```

输出结果示例：
```
=== 最终审计汇总 ===
  风险评分:     65/100 (中危)
  OOM 事件:     3 次
  SSH 爆破:     156 次
  内核错误:     2 条
  异常登录:     5 次
```

**功能3：分布式节点批量远程诊断**

支持多节点并行 SSH 采集，汇总展示：
```
[192.168.1.100]
  CPU: 45.0% ✅  内存: 72.3% ✅  磁盘: 88.5% ⚠️  进程: 234
[192.168.1.101]
```

## 第6页：测试与验证

**测试体系（75 个用例，全部通过）**：

| 测试脚本 | 类别 | 用例数 | 覆盖内容 |
|---------|------|--------|---------|
| `test_patrol.sh` | Mock 单元+集成+异常 | 20 | patrol.sh 全部检查函数、完整巡逻流程、命令降级容错 |

| `test_auto.sh` | Mock 自动化 | 4 | 连续5次一致性、10次无崩溃、无人值守3轮模拟、混合状态 |
| `test_utils.sh` | Mock 单元 | 8 | greater_than（含小数）、command_exists、SSH连接、远程采集 |
| `test_log_analyzer.sh` | Mock 单元 | 12 | 日志源检测、OOM分析、sudo白名单、风险评分（零分+高危） |
| `test_integration_real.sh` | **真实环境** | **16** | 功能4+边界4+异常4+自动化4（含守护进程启停） |
| **总计** | — | **75** | **全部通过，0 失败** |

**典型问题与解决**：
- 日志函数污染标准输出 → 统一重定向至 `stderr`（`>&2`）
- 定时任务相对路径失败 → 动态绝对路径锁定：`ROOT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"`
- 异构文本流单位符号导致算术崩溃 → `gsub(/%/,"")` 统一清洗 + 空值防御 `${var:-0}`
- 非 systemd 环境 `systemctl` 崩溃 → `is_systemd_running()` 双路径检测 + `pgrep -x` 降级
- 测试变量被 `source` 覆盖 → 在 `source` 后强制重新赋值覆盖

## 第7页：开发过程与迭代

**版本演进主线**：

| 版本 | 核心变更 |
|------|---------|
| v1.0 | 主菜单框架 + 3 个业务模块，基础功能实现 |
| v2.0 | 模块解耦重构、WSL 兼容、双格式报告（Markdown+JSON）、31 个测试用例 |
| v3.0 | 测试扩展至 75 个用例、真实环境冒烟测试、README 与文档完善、软件使用说明书 |

**关键迭代节点**：
- **并行采集**：CPU 采集从单次 `top` 改进为 `/proc/stat` 两次差值法，精度大幅提升
- **WSL 兼容**：`dmesg` 在不同 WSL 版本输出格式不一致 → 实现 `dmesg -T` 带时间戳分支处理
- **审计模块**：从简单的 OOM 计数发展为 8 阶段深度分析 + 12 维加权风险评分
- **测试架构**：从 4 个测试脚本 31 例扩展为 7 个脚本 75 例，引入双层测试体系（Mock + 真实环境）
- **守护进程**：从简单 `while true` 循环发展为 nohup + PID 文件管理 + 优雅停止

**每次迭代都解决了具体的技术或工程问题，开发过程记录在 Git 中，可追溯。**
