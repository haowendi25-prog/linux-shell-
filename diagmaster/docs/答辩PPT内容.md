## 第1页：项目简介

**标题**：DiagMaster — 服务器一键智能诊断工具箱

**内容**：
- **项目名称**：DiagMaster v2.0
- **团队**：翟浩雯（组长）、李薇（组员）
- **服务对象**：小型网站维护人员 / 树莓派开发者 / Linux初学者
- **解决的问题**：服务器健康状态不可见，缺少零依赖一键巡检工具
- **一句口号**："像量体温一样简单，输入数字就能完成服务器体检"

---

## 第2页：需求与目标

**现有方法缺陷**：
- 手工执行 `top`、`df`、`free` → 繁琐、不直观
- Prometheus + Grafana → 配置复杂，"杀鸡用牛刀"
- 人工巡检 → 低效、易遗漏

**核心目标**（具体可验证）：
1. ✅ 一键自动巡检6项健康指标（CPU/内存/磁盘/服务/进程/日志安全）
2. ✅ 多源日志安全审计，自动检测 SSH 爆破、OOM 等风险
3. ✅ 生成 Markdown 结构化报告，支持 crontab 定时执行

## 第6页：测试与验证

**测试覆盖**：

| 类型 | 测试用例 | 举例 |
|------|----------|------|
| **功能测试** | 12个 | CPU正常/高负载、内存正常/高占用、磁盘正常/满盘、服务全正常/部分故障、进程存在/缺失、日志无异常/有OOM |
| **异常测试** | 4个 | top不可用降级、df不可用降级、systemctl不可用降级为pgrep、配置文件缺失使用默认值 |
| **集成测试** | 2个 | 全部正常→返回0+报告含"正常✅"、存在异常→返回1+报告含"存在异常" |
| **总计** | **18个** | **全部 PASS** ✅ |

**版本迭代中发现的问题及解决**：
- 日志函数污染 stdout → `>&2` 重定向
- crontab 无法执行 → 改用绝对路径
- 测试变量被 source 覆盖 → 强制覆盖阈值变量
- 不同发行版日志路径不同 → `detect_log_sources` 自动检测
