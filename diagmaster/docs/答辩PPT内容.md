## 第1页：项目简介

**标题**：DiagMaster — 服务器一键智能诊断工具箱

**内容**：
- **项目名称**：DiagMaster v2.0
- **团队**：翟浩雯（组长）、李薇（组员）
- **服务对象**：小型网站维护人员 / 树莓派开发者 / Linux初学者
- **解决的问题**：服务器健康状态不可见，缺少零依赖一键巡检工具
- **一句口号**："像量体温一样简单，输入数字就能完成服务器体检"

---

## 第2页：需求与目标

**现有方法缺陷**：
- 手工执行 `top`、`df`、`free` → 繁琐、不直观
- Prometheus + Grafana → 配置复杂，"杀鸡用牛刀"
- 人工巡检 → 低效、易遗漏

**核心目标**（具体可验证）：
1. ✅ 一键自动巡检6项健康指标（CPU/内存/磁盘/服务/进程/日志安全）
2. ✅ 多源日志安全审计，自动检测 SSH 爆破、OOM 等风险
3. ✅ 后台守护进程模式，支持无人值守持续巡检
4. ✅ 生成 Markdown 结构化报告，支持 crontab 定时执行
5. ✅ 配置化阈值告警，用户无需修改代码

## 第5页：核心功能展示

**功能1：自动巡逻巡检**

输入：选择菜单"5"  
处理：并行检查 CPU/内存/磁盘/服务/进程/日志（6项）  
输出：终端结论 + Markdown 报告

```
示例输出：
===================================
  CPU使用率: 15.2% ✅ 正常
  内存使用:  42.3% ✅ 正常
  磁盘使用:  55%   ✅ 正常
  关键服务:  sshd cron ✅ 正常
  关键进程:  sshd ✅ 正常
  日志异常:  正常（OOM:0, SSH爆破:3）
===================================
巡逻完成：系统状态正常 ✅
报告已生成: reports/patrol_20260606_193749.md
```

**功能2：后台巡逻守护进程**

支持 `--daemon` / `--stop` / `--status` 命令行参数，可实现无人值守持续巡检。

**版本迭代中发现的问题及解决**：
- 日志函数污染 stdout → `>&2` 重定向
- crontab 无法执行 → 改用绝对路径
- 测试变量被 source 覆盖 → 强制覆盖阈值变量
- 不同发行版日志路径不同 → `detect_log_sources` 自动检测
