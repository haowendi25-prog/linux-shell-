## 1. 产品概述

### 1.1 项目简介

DiagMaster 是一款纯 Bash 实现的服务器多维智能诊断工具箱，专为不熟悉 Linux 命令行的运维人员设计。它将复杂的服务器诊断操作封装为 7 个菜单选项——就像使用体温计一样简单：启动程序 → 输入数字 → 自动诊断。

### 1.2 核心价值

| 痛点 | DiagMaster 解决方案 |
|------|---------------------|
| 手工登录多台服务器巡检耗时 | 分布式节点管理，一键批量远程诊断 |
| 系统卡顿无法定位原因 | CPU/内存/磁盘多维并行采集，颜色标记告警 |
| 深夜安全事件无人值守 | 内核日志清洗 + SSH 爆破检测 + 风险评分 |
| 磁盘爆满导致服务宕机 | 多源智能扫描 + 安全删除 + 自愈修复 |
| 无法24小时监控 | systemd 守护进程，定时自动巡检 |

### 1.3 技术架构

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│   diagmaster.sh │◄──►│   modules/*.sh  │◄──►│   lib/utils.sh  │
│   (主入口/UI)   │    │  (业务逻辑)     │    │  (SSH/工具函数) │
└─────────────────┘    └─────────────────┘    └─────────────────┘
         │                       │                       │
         ▼                       ▼                       ▼
  ┌─────────────┐      ┌─────────────┐      ┌─────────────┐
  │  data/      │      │  logs/      │      │  reports/   │
  │  (节点/缓存) │      │  (活动/守护) │      │  (审计/巡检) │
  └─────────────┘      └─────────────┘      └─────────────┘
```

## 2. 系统要求

| 项目 | 最低要求 |
|------|---------|
| 操作系统 | Ubuntu 20.04+ / WSL2 / 其他 Linux 发行版 |
| Shell | Bash 4.0+（推荐 5.x） |

- `awk`, `sed`, `grep`, `df`, `free`, `top`, `ps`, `pgrep`
- （可选）`dmesg`, `systemctl`, `journalctl`, `docker`, `apt-get`

## 3. 安装与启动

### 3.1 快速启动

```bash
# 第 1 步：进入项目目录
cd ~/linux-shell-/diagmaster

# 第 2 步：赋予执行权限
chmod +x diagmaster.sh modules/*.sh tests/*.sh

# 第 3 步：启动主程序
bash diagmaster.sh
```

### 3.2 首次登录

启动后将看到安全认证界面：

```
[安全认证]
请输入管理员账户: admin
请输入安全密码: ******
```

- **默认账户**：`admin`
- **默认密码**：`12345`
- **修改密码**：编辑 `config/diag.conf` 中的 `ADMIN_PASS` 字段

### 3.3 验证安装

```bash
# 运行全部测试用例验证功能完整性
bash tests/run_all_tests.sh

# 预期输出：通过 75 / 失败 0
```

## 5. 模块一：节点资产管理

### 5.1 功能概述

管理分布式服务器的资产信息，支持多节点 SSH 连接测试和批量远程诊断。

### 5.2 子菜单

```
1) 查看节点列表    2) 新增受控节点    3) 删除失效节点
4) 测试节点连接    5) 查看节点详情    6) 批量远程诊断
0) 返回主菜单
```

### 5.3 操作步骤

#### 新增节点
1. 选择 `2) 新增受控节点`
2. 输入目标服务器的 IP 地址或主机名（如 `192.168.1.100`）
3. 系统自动添加到 `data/nodes.txt` 中

#### 批量远程诊断
1. 确保节点列表中已有多个节点
2. 选择 `6) 批量远程诊断`
3. 系统自动并行连接所有在线节点，采集 CPU/内存/磁盘/负载数据
4. 汇总展示结果，异常项红色标记

#### 测试节点连接
1. 选择 `4) 测试节点连接`
2. 输入节点编号
3. 系统执行四重验证：
   - SSH 端口可达性（22端口）
   - SSH 密钥认证状态
   - DiagMaster 安装检测
   - 远程命令执行权限

### 5.4 远程节点前置条件

| 条件 | 说明 |
|------|------|
| SSH 端口开放 | 远程节点需开放 22 端口 |
| DiagMaster 安装 | 远程节点需安装同版本 DiagMaster |
| 密钥认证 | 推荐配置 SSH 公钥免密登录 |

## 6. 模块二：性能监控

### 6.1 功能概述

多进程并行采集关键性能指标（CPU、内存、磁盘、负载、进程数），并通过颜色编码直观展示健康状态。

### 6.2 监控指标与阈值

| 指标 | 采集命令 | 🟢 正常 | 🟡 警告 | 🔴 危险 |
|------|---------|---------|---------|---------|
| CPU 使用率 | `top` / `/proc/stat` | < 80% | 80%-95% | > 95% |
| 内存使用率 | `free` / `/proc/meminfo` | < 85% | 85%-95% | > 95% |
| 磁盘使用率 | `df -h /` | < 90% | 90%-95% | > 95% |
| 系统负载 | `/proc/loadavg` | 视核数 | — | — |
| 运行进程数 | `/proc` 目录 | 信息 | — | — |

### 6.3 操作步骤

1. 主菜单选择 `2) 性能监控`
2. 系统自动检测在线节点并并行采集指标
3. 输出格式如下：

```
[192.168.1.100]
  CPU: 45.0%    ← 绿色（正常）
  内存: 72.3%   ← 绿色（正常）
  磁盘: 88.5%   ← 黄色（警告）
  负载: 0.50, 0.60, 0.55
  进程: 234
```

### 6.4 自定义阈值

编辑 `config/diag.conf`：

```bash
CPU_WARN_THRESHOLD=80   # 修改 CPU 告警阈值
MEM_WARN_THRESHOLD=85   # 修改内存告警阈值
DISK_WARN_THRESHOLD=90  # 修改磁盘告警阈值
```

## 7. 模块三：安全审计

### 7.1 功能概述

深度分析系统日志，检测安全威胁并生成风险评分报告。支持双格式输出（Markdown + JSON）。

### 7.2 审计维度

| 维度 | 检测内容 | 数据源 |
|------|---------|--------|
| 内核稳定性 | OOM（内存溢出）、Panic、Oops | dmesg、kern.log |
| 认证安全 | SSH 失败/成功登录、暴力破解 | auth.log、secure |
| 攻击模式 | 端口扫描、异常登录、用户枚举 | auth.log |
| 用户行为 | sudo 滥用、权限提升、恶意软件 | auth.log、syslog |

### 7.3 风险评分模型

| 风险级别 | 分值范围 | 建议措施 |
|---------|---------|---------|
| 🟢 安全 | 0-19 | 系统健康 |
| 🟡 低危 | 20-49 | 关注趋势，定期复查 |
| 🟠 中危 | 50-79 | 加强监控，检查配置 |
| 🔴 高危 | 80-100 | 立即隔离、取证、排查入侵 |

### 7.4 攻击模式识别

1. **端口扫描检测**：同一 IP 对多个端口的大量失败连接
2. **异常登录检测**：深夜（0-5点）的 SSH 登录行为
3. **用户枚举检测**：大量 `invalid user` 尝试
4. **权限提升检测**：非正常 sudo 使用、UID 切换行为
5. **恶意软件检测**：`xmrig`、`kinsing`、`reverse shell` 等特征

### 7.5 操作步骤

1. 主菜单选择 `3) 安全审计`
2. 系统自动执行 [1/8] → [8/8] 八个审计阶段
3. 完成后展示审计汇总：

```
=== 最终审计汇总 ===
  风险评分:     65/100
  OOM 事件:     3 次
  SSH 爆破:     156 次
  内核错误:     2 条
  异常登录:     5 次
  端口扫描:     3 个源
  恶意软件:     0 条
```

4. 报告保存在 `reports/diag_report_YYYYMMDD_HHMMSS.md` 和同名的 `.json` 文件

## 8. 模块四：磁盘清理

### 8.1 功能概述

智能扫描磁盘垃圾源，按风险分级展示支持安全删除 + 系统自愈修复。

### 8.2 扫描项与风险分级

| 扫描项 | 路径 | 风险级别 |
|-------|------|---------|
| 系统临时文件 | `/tmp`（1天前） | 🟢 低 |
| 用户缓存 | `~/.cache` | 🟢 低 |
| 回收站 | `~/.local/share/Trash` | 🟢 低 |
| apt 包缓存 | `/var/cache/apt/archives` | 🟡 中 |
| journal 日志 | journalctl（7天前） | 🟡 中 |
| 旧内核 | 保留最近2个 | 🔴 高 |
| Docker 悬空镜像 | docker system df | 🔴 高 |

### 8.3 操作步骤

1. 主菜单选择 `4) 磁盘清理`
2. 系统自动扫描并展示垃圾源列表：

```
  # | 类别                          | 大小(MB)  | 风险
  ---------------------------------------------------------
  1 | 系统临时文件 /tmp（1天前）    | 124 MB    | 低
  2 | apt 包缓存                    | 356 MB    | 中
  3 | journal 日志（7天前）         | 512 MB    | 中
```

3. 输入要清理的编号（空格分隔多个，如 `1 3`）
4. 系统执行安全删除并展示释放空间
5. 自动执行自愈：
   - `apt --fix-broken install` 修复依赖
   - `systemctl try-restart` 重启关键服务

### 8.4 安全策略

- **默认勾选**：低风险项自动选择
- **需人工确认**：中、高风险项
- **精确删除**：`grep` / `awk` 精确匹配，不遍历目录树
- **操作日志**：详细记录到 `reports/disk_cleanup_*.log`

## 9. 模块五：自动巡检

### 9.1 功能概述

一键执行 6 项系统健康检查，快速评估服务器整体状态。

### 9.2 检查项

| 编号 | 检查项 | 说明 |
|------|-------|------|
| 1 | CPU 使用率 | 是否超过阈值 |
| 2 | 内存使用率 | 是否超过阈值 |
| 3 | 磁盘使用率 | 根分区是否超过阈值 |
| 4 | 关键服务 | sshd、cron、docker 等是否运行 |
| 5 | 关键进程 | 指定进程是否存在 |
| 6 | 日志异常 | OOM 事件、SSH 爆破检测 |

### 9.3 操作步骤

1. 主菜单选择 `5) 自动巡检`
2. 系统自动执行6项检查并输出结果：

```
## 检查结果汇总
**整体状态: 正常 ✅**

| 检查项 | 状态 | 详情 |
|--------|------|------|
| CPU使用率 | 正常 | 阈值:80% |
| 内存使用率 | 正常 | 阈值:85% |
| 磁盘使用率 | 正常 | 阈值:90% |
| 关键服务 | 正常 | sshd cron |
| 关键进程 | 正常 | sshd |
| 日志异常 | 正常 | OOM/SSH爆破 |
```

3. 报告保存在 `reports/patrol_YYYYMMDD_HHMMSS.md`

## 10. 模块六：后台守护

### 10.1 功能概述

将自动巡检封装为后台守护进程，按固定间隔（默认300秒）定时执行。

### 10.2 子菜单

```
1) 启动守护进程    2) 停止守护进程    3) 查看运行状态
0) 返回主菜单
```

### 10.3 操作步骤

#### 启动守护进程
1. 选择 `1) 启动守护进程`
2. 守护进程在后台启动，每 300 秒执行一次巡逻
3. 日志输出到 `logs/patrol_daemon.log`

#### 查看运行状态
1. 选择 `3) 查看运行状态`
2. 输出守护进程 PID 和运行状态：

```
巡逻守护进程正在运行 (PID: 12345)
```

### 10.4 命令行快速操作

```bash
# 一键启动守护进程
./diagmaster.sh --daemon

# 停止守护进程
./diagmaster.sh --stop

# 查看状态
./diagmaster.sh --status
```

## 11. 命令行模式

适合集成到自动化脚本或定时任务（cron）：

```bash
# 一次性巡检（适合 crontab 定时任务）
./diagmaster.sh --patrol

# 启动后台守护（需 root 权限）
sudo ./diagmaster.sh --daemon

# 停止守护
./diagmaster.sh --stop

# 查看守护状态
./diagmaster.sh --status

# 显示帮助
./diagmaster.sh --help
```

**cron 定时任务示例**（每30分钟巡检一次）：
```bash
*/30 * * * * cd /path/to/diagmaster && ./diagmaster.sh --patrol
```

## 12. 配置文件说明

配置文件位于 `config/diag.conf`，修改后下次运行自动生效，无需重启。

```bash
# ─── 性能阈值（百分比）───
CPU_WARN_THRESHOLD=80       # CPU 告警阈值
MEM_WARN_THRESHOLD=85       # 内存告警阈值
DISK_WARN_THRESHOLD=90      # 磁盘告警阈值

# ─── 管理账户 ───
ADMIN_USER="admin"          # 登录用户名
ADMIN_PASS="12345"          # 登录密码（正式使用请修改）

# ─── 审计配置 ───
AUDIT_DAYS=7                # 审计回溯天数
OOM_WARN_THRESHOLD=5        # OOM 告警阈值
SSH_FAIL_WARN_THRESHOLD=30  # SSH 失败告警阈值
MAX_LOG_LINES=10000         # 日志分析最大行数

# ─── 后台守护配置 ───
ENABLE_AUTO_HEAL=true       # 是否启用自愈
PATROL_INTERVAL=300         # 巡逻间隔（秒）

# ─── 检查项 ───
SERVICES_TO_CHECK="sshd cron docker"   # 需检查的服务
PROCESSES_TO_CHECK="sshd"              # 需检查的进程
```

## 14. 常见问题解答

### 14.1 运行报 "Permission denied"

```bash
chmod +x diagmaster.sh modules/collector.sh modules/patrol.sh modules/log_analyzer.sh
```

### 14.2 忘记管理员密码

编辑 `config/diag.conf`，修改或删除 `ADMIN_PASS` 行（删除后回退默认密码 `12345`）。

### 14.3 想增加检查服务/进程

编辑 `config/diag.conf`，修改：

```bash
SERVICES_TO_CHECK="sshd cron nginx mysql postgresql"
PROCESSES_TO_CHECK="sshd nginx"
```

### 14.4 WSL 环境下审计报告显示内核错误

WSL 环境下 `dmesg` 可能包含虚拟化驱动警告，非真实内核崩溃。建议在 `.wslconfig` 中调整资源限制。

### 14.5 安全审计报告在哪里

- Markdown 格式：`reports/diag_report_YYYYMMDD_HHMMSS.md`
- JSON 格式：`reports/diag_report_YYYYMMDD_HHMMSS.json`

### 14.6 磁盘清理会误删文件吗

不会。DiagMaster 使用精确的 `find` 条件过滤（如只删 `/tmp` 下 1 天前的普通文件），以及 `du` 先做大小统计——不遍历目录树，不做递归删除。中、高风险项需要人工确认。
